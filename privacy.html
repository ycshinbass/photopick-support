한국어

Photopick은 사용자가 로그인한 Google 포토의 중복 후보와 비슷한 장면을 기기에서 비교합니다. Google과 제휴하거나 Google이 보증하는 프로그램이 아닙니다.

  • 사진 처리: 미리보기·파일 식별자·촬영일·형식·해상도·용량 및 확인 가능한 HDR 정보를 읽습니다. HDR은 원본 메타데이터 구간을 제한적으로 읽습니다. 동영상은 컨테이너 색상 정보와 영상 내부의 HDR 표시를 읽습니다. 부분 읽기가 가능하면 압축 데이터를 건너뛰고, 지원되지 않으면 순차 읽으면서 압축 데이터는 즉시 버립니다. HDR 응답 본문 읽기 예산은 원본당 256 MiB, 작업당 8 GiB이며 중지·재개에도 누적합니다. 2.17.5·2.17.6 beta와 2.18.0에서 이력 저장을 끈 경우, 한 그룹을 다시 확인할 때 별도 8 GiB 예산을 씁니다. 2.18.0에서 이력을 저장한 작업의 재개·그룹 재확인은 기존 작업 예산에 누적합니다. 이 수치는 브라우저 자체의 선행 네트워크 버퍼를 포함한 전송량 보장은 아닙니다. 컨테이너 메타데이터는 최대 512 KiB, 샘플 위치 표는 최대 100,000개(약 1.2 MB), 개별 HDR 표시 내용은 최대 64 KiB까지 메모리에 잠시 보관합니다. 원본 파일을 디스크에 저장하지 않습니다. 영상 전체와 음성 전체의 동일성을 검증하지 않습니다.
  • AI 장면 비교: ‘비슷한 사진’과 ‘정확 모드’를 함께 고르면 확장에 포함된 이미지 모델(DINOv2-small, Apache-2.0)이 이 기기 안에서 작은 미리보기의 특징값을 계산합니다. 모델은 내려받지 않고 확장에 들어 있으며, 사진과 특징값을 개발자나 외부 분석 서비스에 보내지 않습니다. 특징값은 브라우저 메모리에서 처리합니다.
  • 추천 사진 품질 확인: 같은 조건에서 비슷한 장면 그룹의 640px 미리보기를 Google 서버에서 읽어, 확장에 포함된 얼굴 모델(MediaPipe Face Landmarker, Apache-2.0)과 초점 계산으로 눈 감음·고개 돌림·시선·흐림 여부를 이 기기 안에서 확인합니다. 얼굴을 알아보거나 사람을 식별하지 않으며, 결과 수치는 브라우저 메모리에서 처리하며, 최종 추천 내용은 아래 임시 결과 사본에 포함될 수 있습니다. 사진과 수치를 개발자나 외부 분석 서비스에 보내지 않습니다.
  • 통신: Google 포토와 Google 이미지 서버에 미리보기와 파일 정보를 요청합니다. 목록과 파일 정보를 조회할 때는 이미 로그인한 Google 포토 페이지의 세션 값을 읽어 Google 포토에만 보냅니다. 이 값을 확장 저장소에 보관하거나 개발자·외부 분석 서비스에 전송하지 않습니다. 프로필 파일·비밀번호·쿠키를 추출하지 않습니다. 동의한 뒤에는 열린 Google 포토 탭의 관련 응답에서 파일 정보를 읽어 해당 탭의 메모리에서 재사용할 수 있습니다. 사진·사진 주소·분석 결과를 개발자나 외부 분석 서비스에 보내지 않습니다.
  • 정보 조회 창: 파일 정보를 확인할 때(정확 모드나 ‘사진 정보 다시 확인’) 목록만으로 형식·해상도·용량을 알 수 없는 사진이 있으면, 포토픽이 뒤쪽에 작은 Google 포토 창을 잠시 열어 그 사진의 정보 패널을 읽습니다. Chrome의 debugger 권한은 포토픽이 직접 연 이 창에만 연결해 포커스 상태를 모사하는 데 씁니다. 사용자가 연 다른 탭·창에는 연결하지 않고, 네트워크·쿠키·저장소를 들여다보는 명령을 쓰지 않습니다. 조회가 끝나거나 중지되면 연결을 해제하고 창을 닫습니다.
  • 공통 설정과 암호화한 임시 사본: 비교 결과와 크기/유효기간이 제한된 사진 정보 캐시는 기본적으로 현재 탭 메모리에 둡니다. 언어·테마·개인정보 처리 동의와 마지막 검색 설정(검색 종류·비교 방식·기간)은 확장 저장소에 보관합니다. 탐색 설정은 짧은 유효기간의 세션 저장소를 사용합니다. 업데이트(복원 유효기간 30분)와 원래 목록으로 복귀할 때(2분) 만드는 임시 사본에는 사진 주소·파일 정보·비교 및 추천 결과가 포함됩니다. v2.17.5부터 만드는 이 사본은 기기에서 AES-GCM으로 암호화하여 확장 전용 로컬 저장소에 보관합니다. 키는 내보낼 수 없는 형태로 같은 Chrome 프로필의 확장 전용 저장 영역에 보관합니다. 복원을 확인하거나 목록 복귀가 안정되면 사본을 제거합니다. 종료나 중단으로 남은 만료 사본은 다음 백그라운드 실행·브라우저 시작 때 정리하며, 만료된 사본은 복원하지 않습니다. 2.18.0은 2.17.6 beta가 업데이트 직전에 남긴 사본도 기존 유효기간 안에서 읽을 수 있습니다. 브라우저 종료·새로고침 후 복원되는 검사 이력은 아래의 별도 기능입니다.
  • 2.18.0의 검사 이력과 별도 동의: 사진 처리 동의와 별도로 이 기기에 검사 이력을 저장할지 묻습니다. 저장에 동의하면 확장 전용 IndexedDB에 계정 확인용 지문, 검사 범위와 진행 위치, 사진·영상 식별자와 비교 근거, 보관·보류 결정, 원본 읽기 예약과 누적 사용량을 저장합니다. 이력에는 원본 파일, 다운로드 주소 또는 인증정보가 저장되지 않습니다. 저장된 작업은 같은 계정과 목록을 확인한 뒤 복원합니다. 저장에 동의하지 않아도 이력 없이 검사할 수 있습니다.
  • 2.18.0의 검사 이력 보호: 검사 이력은 Chrome 프로필과 확장 원점의 접근 보호를 이용합니다. 위에서 설명한 임시 사본은 별도로 AES-GCM을 사용합니다. ‘이 기기의 검사 기록’에서 현재 계정의 이력을 지우고 앞으로의 저장을 끌 수 있습니다. 기록 삭제는 Google 포토 사진에 영향을 주지 않습니다.
  • 2.18.0의 선택 기록과 권한: 저장한 작업의 선택을 승인하면 대상·보관 지문, 현재 문서에 연결된 10분 승인, 체크 의도와 관측 결과를 기록합니다. 복구는 현재 체크 상태를 읽어 대조하고 Google 포토 최종 이동은 사용자가 확인합니다. 2.18.0은 저장 작업 복구를 위해 Chrome 알람 권한을 추가합니다. Google 포토와 이미지 서버의 호스트 범위, 파일 정보 창에 한정한 디버거 사용은 2.17.6 beta와 같습니다.
  • 무료 베타: 현재 기능은 모두 무료이며 결제·7일 체험 제한·별도 Google/이메일 인증이 없습니다. 결제 SDK와 개발자 운영 계정/체험 서버가 없고, 광고·행동 분석을 하지 않습니다. 포함된 얼굴 모델 라이브러리(MediaPipe)에 들어 있는 사용 통계 기록은 꺼 두었으며, 확장의 통신 제한(Google 포토·Google 이미지 서버만 허용)으로도 차단합니다. 향후 별도 유료 기능이나 데이터 처리 방식이 추가되면 이용 조건과 개인정보 안내를 갱신합니다.
  • 사용자 제어: 스캔·비교를 중지하고 완료한 결과를 검토할 수 있습니다. 초기화는 사진 자체가 아니라 분석·선택 준비를 지웁니다. 실제 휴지통 이동은 선택 검토와 Google 포토의 최종 확인을 거칩니다. 복원과 보관 기한은 Google 포토 안내를 따릅니다. 확장 제거 또는 Chrome의 확장 데이터 관리로 저장 정보를 지울 수 있습니다.
  • 공유: 사용자 데이터를 판매하거나 광고 목적으로 공유하지 않습니다. 지원 요청에 개인 사진·주소·계정·인증정보를 올리지 마세요.
  • 제한적 사용: Photopick은 Google 포토에서 얻은 정보를 안내한 사진 비교·정리 기능에만 사용하며, Chrome 웹 스토어 사용자 데이터 정책의 제한적 사용(Limited Use) 요건을 준수합니다.
  • 지원 사이트와 문의: 안내 사이트는 GitHub Pages에서 제공하며 GitHub가 보안을 위해 접속 IP 주소를 기록할 수 있습니다. 이메일 문의를 보내면 답변에 필요한 이메일 주소와 문의 내용을 지원 담당자가 처리합니다. 문의에 개인 사진이나 인증정보를 포함하지 마세요.

English

Photopick compares candidates in the Google Photos account you use, on your device. It is not affiliated with or endorsed by Google.

  • Media: It reads previews, file identifiers, capture dates, formats, dimensions, sizes and available HDR metadata. HDR checking reads bounded original metadata ranges. For videos, it checks container colour information and HDR signalling inside the video. Compressed payloads are skipped when range reads work, or discarded during a sequential read otherwise. HDR response-body read budgets are 256 MiB per original and 8 GiB per scan, including pause/resume. Refreshing details for one group has its own 8 GiB budget in 2.17.5–2.17.6 beta and in 2.18.0 when local history is off. In 2.18.0, resumed scans and group refreshes for a saved task count toward that task’s existing budget. These counters do not guarantee total network transfer including browser prefetch buffers. Temporarily retained data is limited to 512 KiB of container metadata, 100,000 sample positions (about 1.2 MB), and 64 KiB per HDR signalling unit. No original media file is saved to disk. Full video/audio identity is not verified.
  • On-device scene model: With *Similar photos* and *Accurate mode*, a bundled image model (DINOv2-small, Apache-2.0) computes features of small previews on this device. The model ships inside the extension; photos and features are not sent to the developer or external analysis services. Features are processed in browser memory.
  • Keeper quality check: Under the same settings, 640px previews of similar-scene groups are read from Google servers and checked on this device for closed eyes, turned heads, gaze and blur using a bundled face model (MediaPipe Face Landmarker, Apache-2.0) and a focus measure. It does not recognize or identify people. Scores are processed in browser memory; final recommendations may be included in the temporary result copies described below. Photos and scores are not sent to the developer or external analysis services.
  • Network: Preview and file detail requests go to Google Photos and Google image servers. To read media lists and details, Photopick uses existing session values from the signed-in Google Photos page in requests to Google Photos only. It does not keep those values in extension storage or send them to the developer or external analytics services. It does not extract browser profile files, passwords or cookies. After consent, it can read file details from relevant responses in open Google Photos tabs and reuse them in the same tab's memory. Photos, private photo URLs and analysis results are not sent to the developer or external analysis services.
  • Information window: When checking file details (Accurate mode or Refresh photo details) and the list does not show a photo's format, dimensions or size, Photopick briefly opens a small Google Photos window in the background and reads that photo's info panel. The Chrome debugger permission is attached only to this window that Photopick opened, to emulate focus. It is never attached to tabs or windows you opened, and no network, cookie or storage inspection commands are used. The connection is released and the window closed when the lookup ends or is stopped.
  • Shared settings and encrypted temporary copies: Bounded result and photo-information caches normally remain in tab memory. Language, theme, consent and the last search settings (search type, comparison method and period) use extension storage. Navigation settings use short-lived session storage. Temporary update and library-return copies include photo URLs, file details, comparison results and recommendations. Starting with v2.17.5, these copies are encrypted on-device with AES-GCM and held in extension-private local storage. The non-exportable key stays in extension-private storage in the same Chrome profile. Update copies are valid for restoration for 30 minutes and library-return copies for 2 minutes. Copies are removed after successful restoration or a stable return. Expired copies left after interruption are removed when the background next starts or Chrome restarts and cannot be restored. Version 2.18.0 can restore a copy left immediately before an update by 2.17.6 beta within its original time limit. The separate history feature below handles saved results after a page refresh or browser restart.
  • 2.18.0 history and separate consent: Photopick asks separately whether to save scan history on this device. If enabled, extension-private IndexedDB stores a local account digest, scan scope and position, file identifiers, comparison evidence, keep/defer decisions and original-read reservations and usage. The history excludes original files, download addresses and credentials. Recovery checks the same account and list. Scans can also run without saved history.
  • 2.18.0 scan-history protection: Scan history uses Chrome profile and extension-origin access protections. Temporary copies use the separate AES-GCM protection described above. Use Scan history on this device to clear the current account’s history and disable future storage. This does not change your Google Photos.
  • 2.18.0 selection records and permissions: Selection approval for a saved task records fingerprints of targets and keepers, a ten-minute document-bound approval, and intended and observed checkbox states. Recovery checks the current state. The user confirms the final move in Google Photos. 2.18.0 adds the Chrome alarms permission for saved-task recovery. The Google Photos and image host scope and the debugger’s limitation to the file-information window match 2.17.6 beta.
  • Free beta: All current features are free. There is no payment, seven-day trial limit, added Google/email sign-in, billing SDK or developer-operated account/trial server, and no advertising or behavioral analytics. The usage-statistics log inside the bundled face-model library (MediaPipe) is switched off and is also blocked by the extension's network restrictions (Google Photos and Google image servers only). Separate paid features may be introduced later with updated terms and privacy disclosures.
  • Control: Stop tasks and review completed work. Reset clears analysis and prepared selections, not the photos themselves. Actual moves require selection review and final confirmation in Google Photos. Restoration follows the Google Photos retention notice. Uninstall or use Chrome's extension-data controls to remove stored data.
  • Sharing: Data is not sold or shared for advertising. Do not include private photos, URLs, account details or authentication values in public support requests.
  • Limited Use: Photopick uses information obtained from Google Photos only for the photo comparison and organization features described here, in compliance with the Chrome Web Store User Data Policy, including its Limited Use requirements.
  • Support site and contact: This documentation site is hosted by GitHub Pages, which may log visitors’ IP addresses for security. If you contact support by email, your email address and message are handled to respond to your request. Do not include private photos or authentication information.
